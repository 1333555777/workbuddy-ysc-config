佳佳在线 · 影视仓配置 使用教程

把 10 个公开影视源聚合、自动保鲜，再填进影视仓 / TVBox App 即可看片。
⚠️ 当前状态：仓库已建好，但还只是本地文件，没有上线。
README 里的订阅链接现在还是 GITHUB_USER 占位符，影视仓 App 暂时拉不到。
要让 App 用上，请走下面 方案 A 把仓库推到你的 GitHub（一次性，约 5 分钟），再填 CDN 链接。
想立刻看片、先不部署，见 方案 B。

一、整体数据流（看懂这个就不会填错）

推荐 · 自动保鲜
方案 A：部署到 GitHub

推一次，之后每天自动更新源、自动续命。App 里填 CDN 链接，长期稳定可用。

零部署 · 立刻看
方案 B：直接用原始源

不部署仓库，App 里直接填佳佳在线的原始地址先看片。缺点：没有聚合保鲜，源挂了要自己换。

二、方案 A · 部署到 GitHub（详细步骤）

1

准备两样东西

  • 一个 GitHub 账号（没有就去 github.com 注册，免费）。
  • 电脑上装好 Git（没装去 git-scm.com 下载安装，一路下一步）。
2

在 GitHub 新建一个空仓库

登录 GitHub → 右上角 + → New repository。

  • Repository name：workbuddy-ysc-config（必须和脚本里一致，否则链接对不上）
  • 选 Public（私有仓库 jsDelivr CDN 拉不到）
  • 不要勾选 "Add a README file" / .gitignore / LICENSE（仓库要空着，由推送脚本初始化）
  • 点 Create repository
最容易填错：仓库名要和脚本里写死的一致（workbuddy-ysc-config）。改了名就得同步改 update.py 的 REPO、README、两个 bat —— 别自找麻烦，先用这个名。
3

改两个 bat 里的占位符（关键！）

仓库文件夹里有两份 bat：push-tvboxy.bat 和 一键推送-自动读剪贴板.bat。用记事本打开，把下面两处改成你自己的：

占位符改成在哪几行
GITHUB_USER你的 GitHub 用户名REMOTE_URL、credential.username、结尾的订阅/actions 链接
C:\Users\Administrator\Desktop\workbuddy-ysc-config你本地实际放仓库的文件夹路径REPO_DIR（第 13 行）
最容易填错： ① GITHUB_USER 没全替换（共出现 4~5 处，用记事本的"替换全部"一次改完）；
② REPO_DIR 还指向 Desktop\... 旧路径 —— 改成你真实路径，否则脚本找不到文件直接退出。
4

生成 GitHub 令牌（PAT）

GitHub → 右上角头像 → Settings → 左侧最底 Developer settings → Personal access tokens → Tokens (classic) → Generate new token (classic)。

  • Note：随便写，如 tvbox-push
  • Expiration：选 No expiration（或 90 天，到期再换）
  • 勾选 repo（整组勾上，含私有库权限）
  • 额外勾选 workflow（⚠️ 不勾这个就推不了自动更新工作流！）
  • 翻到底点 Generate token → 立刻 复制 那串 ghp_xxx（只显示一次）
最容易漏：忘记勾 workflow scope。没有它，CI 工作流文件推不上去，以后就不能自动更新了。
5

双击 bat 完成推送

推荐用 一键推送-自动读剪贴板.bat：

  • 先把第 4 步复制的 token 留在剪贴板（Ctrl+C 复制后别动）；
  • 双击 一键推送-自动读剪贴板.bat；
  • 脚本自动读剪贴板里的 token → 写入 token.txt → git 初始化/提交/推送；
  • 看到 "推送完成" 即成功。失败看窗口红字（多半是步骤 3 的占位符没改对）。
推送成功后，去 GitHub 仓库页面就能看到 output/ 文件夹和 README 了。
6

手动跑一次工作流，刷新产物

工作流是"定时+手动"，不会因为推送就自动跑。需要手动触发一次：

  • 仓库页 → 上方 Actions → 左侧 Auto Update TVBox Configs → 右侧 Run workflow → 确认跑绿色 ✓；
  • 跑完回到仓库，output/all.json、output/subscribe.json 会被重新生成，README 状态表也刷新成最新；
  • 之后每天 10:00 / 22:00（北京时间）自动跑，不用再管。

三、在影视仓 App 里填订阅地址

工作流跑完后，把下面链接里的 GITHUB_USER 换成你的用户名，填进 App 的「设置 → 配置地址」。

你的客户端该填哪个文件地址（替换 GITHUB_USER）
影视仓 / 支持多仓切源的客户端 多仓订阅 https://cdn.jsdelivr.net/gh/GITHUB_USER/workbuddy-ysc-config@main/output/subscribe.json
鳄鱼影视仓 / takagen99-Box 编译版 单仓聚合 https://cdn.jsdelivr.net/gh/GITHUB_USER/workbuddy-ysc-config@main/output/all.json
最容易填错：单仓盒子（takagen99-Box 等）必须填 all.json。填成 subscribe.json 会因顶层没有 sites 字段而报「解析配置失败」。
✅ 填完点「确定 / 加载」，等几秒出分类栏即成功。以后源更新全自动，App 里重新加载配置即可。

四、方案 B · 不想部署，现在就看片

跳过 GitHub，App 里直接填佳佳在线的原始地址（已验证为合法单仓配置）：

单仓①：https://jijietvbox.lol/xiaosha.json 单仓②：https://jijietvbox.lol/jieluntan-fty.json

在 App「设置 → 配置地址」填上面任意一个即可。缺点：没有聚合保鲜，某源挂了得自己换地址。等哪天想省心了，再走方案 A。

五、常见问题

  • App 报「拉取配置失败」？ 网络层问题（DNS 污染/超时）。国内一律用 cdn.jsdelivr.net 链接，别用 raw.githubusercontent.com。jsDelivr 偶尔抽风可换 ghfast.top/https://raw... 前缀。
  • App 报「解析配置失败」？ 格式不对——单仓盒子填了多仓订阅。换 all.json。
  • 某个源一直失败？ 影视源域名寿命很短，是常态。脚本已做多地址回退，只把成功的写入；偶尔去 config/sources.json 把死的源换掉再推一次即可。
  • 分类出来了但内容转圈？ 部分 Box 编译版冷启动 bug，与配置无关，重启 App 或重编译解决。
